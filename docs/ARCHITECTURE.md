# 架构与扩展

程序入口位于 `src/app.cpp`：`inspect` 读取元数据，`render` 处理单景，`mosaic` 从 JSON
任务读取 MERSI 数据/GEO 配对。JSON 相对路径以任务文件所在目录为基准。

`include/raster.hpp` 定义带尺寸检查的栅格、经纬度网格、有效掩膜与产品帧；
`include/pipeline.hpp` 是地图流程接口。`Request` 汇总产品与地图参数；`GeoProjection` 负责
从原始经纬度投到地图平面；`src/pipeline.cpp` 负责统一范围、重叠归属、经纬网、色标及输出。
拼接时保留原始地理定位网格，栅格化使用每个观测像元的地理四角；在重叠处选择更接近
扫描中心的有效像元，时间和输入路径决定平局顺序。
经纬网默认关闭；单景命令通过 `--grid`、拼接任务通过 `map.grid: 1` 开启。

`src/mersi.cpp` 是 MERSI 与已有产品算法之间的桥接层。旧算法集中在 `include/legacy/`，
通过 `CapturedScene` 提供带经纬度的产品图像；`src/legacy.cpp` 承接 FY4、MWRI、PMR
和 GIIRS 现有模式。MERSI 单景保留旧版投影和裁剪语义，捕获产品颜色及完整标签后，
交回旧版 `rend_cl` 成图；单景不经过拼接的共同拉伸或栅格化。
`include/legacy/draw.h` 在旧版画布坐标上叠加可选 grid，绘制范围限制在主体地图内。
旧版标题、坐标、页脚及色条绘制由 `rend.h` 保留，拼接也复用该代码。
新产品应在桥接层提供数值栅格与有效掩膜，让拼接的全任务显示统计在着色前完成。

新增 MERSI 产品时，先定义输入波段、校正和产品值，返回同尺寸数值栅格与有效性；
然后在产品分派中注册模式。新载荷应建立单独的读取适配器，将数据和 GEO 统一为
栅格及原始经纬度，再复用 `GeoProjection` 与地图输出。不得在产品算法中调用文件输出。

拼接时 MERSI `E` 模式使用所有轨段的共同亮温范围；`RT`、`RY`、`RMUL` 使用共同的
99% 反射率拉伸。其他使用场景局部百分位拉伸的合成模式可拼接，但仍可能出现亮度接缝。
对这些模式迁移数值产品时，
需要将拉伸统计移到全任务阶段。多景只接受文件名带 `YYYYMMDD_HHMM` 和分辨率的输入；
每份 GEO 必须显式配对。

旧版源码基线保存在 Git 标签 `legacy-baseline`。真实数据、任务文件和输出图片都被
`.gitignore` 排除，不应强制加入仓库。
